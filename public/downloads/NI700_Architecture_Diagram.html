Diagram 1 — ni700_top — High-Level Architecture
DUT at centre with all 26 master ports on the left and all 18 slave ports on the right (from the Master_Slave_mapping_main_Ni700 and Main_NI700_port_description sheets). Every port has its own interface and its own UVM Agent (master agents drive requests; slave agents act as responders). Q-Channel and Debug sideband agents are also shown. Arrows show direction: → input to DUT · ← output from DUT · ↔ bidirectional.

Diagram 2 — ni700_top — UVM Testbench Hierarchy
Full UVM TB hierarchy wrapped inside tb_top. Optimised: a single axi_master_agent class (instantiated 26 times) and a single axi_slave_agent class (instantiated 18 times) are shown once each, with one virtual-interface array per side (axi_mst_if[26], axi_slv_if[18]). Per-port behaviour comes from config objects. Active agents (driver + sequencer + monitor) in green. Virtual sequencer inside env connects to all active sequencers (AXI master, AXI slave, Q-channel, debug, clock, reset). All monitors send transactions to scoreboard AND coverage via analysis ports. The test box holds the virtual sequence and the env. Clock and reset each have their own agent and virtual interface, matching Diagram 1.
